# Feature backlog (pre-release candidates)

Ideas to consider before release. Not scheduled into a sub-project yet; each
gets its own brainstorm → spec → plan when picked up.

| Feature | Notes |
|---|---|
| Fugue sequencing | Generate or assist imitative counterpoint (subject, answers, entries at intervals/delays). |
| Euclidean sequencing | Distribute k hits over n steps (with rotation) per lane/track. |
| Aleatoric sequencing | Chance-driven sequencing: probabilities, random choice among events, constrained randomness. |
| Audio (generative / sequencing for audio) | Clarify scope: apply the sequencing modes above to audio regions/slices? |
| Live looping (Boomerang-style) | Real-time audio looper: record, overdub, reverse, once, stack; sync to tempo or free. |
| Four themes (SP7) | 1. SVP Light (Studio Vision Pro 4.5-inspired). 2. Cubase Dark (modern dark). 3. Metro UI (below). 4. Realistic, Soundcraft-console-inspired: skeuomorphic hardware look — textured panel, real-looking fader caps colour-coded by strip type, coloured knob caps by function (EQ bands, aux, pan), as in the Spirit M8 reference. All inspiration only: no vendor names, logos, fonts or artwork. **Shared across all four themes:** fader caps colour-coded by strip type (channel, aux/return, bus, master) and knob/control caps colour-coded by function (EQ bands, aux sends, pan, gain); each theme renders them in its own style (flat tiles in Metro, hardware caps in Realistic, etc.). |
| Theme inspired by Metro design and the Zune devices (https://en.wikipedia.org/wiki/Metro_%28design_language%29) | One of the four themes: flat, typography-led (large light-weight type, content over chrome), bold single accent colours on black or white, edge-to-edge panels and panoramic/pivot navigation, minimal borders and gradients. Inspiration only: no Microsoft or Zune logos, fonts or assets (use our own or open fonts). |
| Built-in EQ and dynamics from ZL Audio's open-source plugins (https://zl-audio.github.io/plugins/) | Candidates for the channel strip's EQ and dynamics, e.g. their equalizer and compressor. Verify each plugin's licence before reusing code (believed AGPL-3.0; that combines with our GPL-3.0 under GPL §13, but confirm). Using them as bundled CLAP/VST3 plugins avoids merging code. Fits the colour-coded EQ in the SP7 mixer refinements. |
| Built-in instruments/effects from Mutable Instruments' open-source DSP | Port the open-source Eurorack DSP code (e.g. macro-oscillator, granular texture, resonator, modal and string models) as built-in or CLAP plugins. Check each module's licence (most DSP is MIT; some files differ) against GPL-3.0 and keep notices. Use our own names and UI, not the Mutable Instruments trademarks or panel art. |
| SP7 control libraries (candidates) | **AudioKit Controls** (SwiftUI knobs, faders, XY pads, wheels, ribbons; MIT): base or reference for our themed controls. **bradhowes/AUv3Controls** (SwiftUI knob/toggle; MIT): borrow its interaction — vertical drag, fine adjustment the further the pointer moves away, typed values. **AudioKit Waveform** (Metal renderer): reserve only; 5b already draws from Rust overviews, consider if drawing many tracks is slow. **AudioKit Keyboard/PianoRoll**: reference only for the on-screen keyboard look; keep our own editors. **AudioKit Flow** (SwiftUI node graph): possible future routing-matrix view. **cutoff/audio-ui** (web): visual reference only (vector knob rings, LED buttons, channel strips). Before adopting any: verify the licence file, maintenance, macOS (not just iOS) support, minimum macOS/Swift versions, and that it doesn't pull in the full AudioKit engine; keep MIT notices. |
| Low Latency Mode (Logic Pro style) | While a lane's input is monitored, bypass plugins on its path whose latency exceeds a limit (default 5 ms); they return when monitoring stops. Deferred from SP5 plan 5d by owner decision (spec Ruling 33). |
| Live MIDI through software instruments without compensation delay | Plan 5d-1 leads audio regions so a monitored *audio* input waits for no other path (Ruling 2). A plugin instrument played live through thru still waits for the mix's latency: its strip's compensation delay would have to move ahead of the instrument, scheduling its MIDI early (Logic's "live mode" for the selected track). Kept PDC-delayed in 5d-1 by controller ruling C1. |
| Strip automation aligned by each strip's arrival time | Automation applies at the renderer's frame on every strip, so a strip whose inputs arrive late (master, a bus behind a latent path, an audio path whose regions are led since plan 5d-1, Ruling 5) moves up to that much early: on a read-ahead (led) path, up to one lead. Offset each strip's automation by its PDC arrival time. Accepted for 5d-1 by controller ruling C2; plan 5e (automation recording) is the natural owner. |
| Per-node lead fallback for sidechains | Plan 5d-1 drops every region lead in the graph when a sidechain runs from a led path into a strip with latency after it (Ruling 2's fallback), so one such sidechain puts every monitored input back behind the mix's latency. Zero only the leads feeding the offending sidechain, and iterate (at most one pass per node) until no sidechain is misaligned (pre-flight M2). |
| Led regions after a loop edit that follows earlier wraps | A led path counts the passes it has already read ahead as passes of the loop now set, so a loop edit after earlier wraps whose stretch to the next wrap is shorter than the lead plays up to one lead of the old loop's frames once (measured: 800 frames of a 10 000-frame loop shrunk to 2 000 after four wraps). No underrun. A fix keeps a history of the loop's stretches (plan 5d-1 Task 2 review P2). |
| Arm's engine claim off the session lock | Plan 5d-1 m8: an arm can block the main thread while `claim_host` retires or rebuilds a host, or connects MIDI sources. Move the claim off the session lock. |
| streamed_render_equals_cached_render seed after a locate | `core-engine/tests/audio_playback.rs` `streamed_render_equals_cached_render` fails deterministically for the seed line in carry #17 (it fails since 37bd7bd); random runs pass. Find out whether the streamed render or the cached one is wrong after a locate. |
| Count-in survives a device rebuild | Carry #6: if the audio device restarts during the count-in (another device chosen, a sample-rate change), the rest of the count-in is skipped and recording starts at once. Keep the count-in running across the rebuild. |
| Destination editor (return latency, Measure) | Spec §6.7: a destination editor with the return latency field and a Measure button. Today Measure is reachable from the Track Synth sheet and `destination.measure_return`. |
| Input pickers' MIDI source list off the main thread | Plan 5d-2 final review m4: `LaneInputs.groups` lists the CoreMIDI sources (`midiSourcePorts()`) on the main thread each time a MIDI lane's picker opens, and while a mixer strip for a lane with no input renders; on a cold CoreMIDI server the first call can stall the window. Cache the list and refresh it from CoreMIDI's setup-changed notification off the main thread (same class as the arm-claim row). |
| Two count-in clicks in one block after a latency drop | Plan 5d-1 carry N1: if the output latency drops by more than one beat during a count-in (a device change), two count-in clicks can land in the same block. Note only: no fix planned until a device change during a count-in is supported (see "Count-in survives a device rebuild"). |
| Input devices keyed by UID | Plan 5d-2 final review m3: Settings › Audio stores and selects the input device by name, so two identical interfaces (same name) are ambiguous. Store the device UID with the name. |
