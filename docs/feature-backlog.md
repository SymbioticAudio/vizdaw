| Count-in survives a device rebuild | **Scheduled: 27.1.0 (moved from 26.0.0 on 2026-11-16, plan release-fixes Task 1).** The engine already resumes the count-in: a rebuild during it plays only the beats left, from the next beat, with the timeline at the record start (`Counting::new`'s `done`, `Engine::count_in_progress`, `PendingPlay::resume_count_in`). But a device rebuild still ends a recording pass, MIDI-only ones included: the pass records through the old engine's record tap, which closes with it, so the next `idle` ends the pass ("the audio device went away") and stops the transport. The fix is to keep a MIDI-only pass alive across a rebuild: install a new tap on the rebuilt engine and hand the pass its new handles (audio passes still end). Also: a rebuild while a counted Play waits for the disk (after `play`, before `finish_play`) resumes without the count-in, because the host learns the count-in only in `finish_play`. Carry #6: if the audio device restarts during the count-in (another device chosen, a sample-rate change), the rest of the count-in is skipped and recording starts at once. Keep the count-in running across the rebuild. |
