# VizDAW 5d-2 — Record UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recording is driven from the app's own windows: a toolbar Record button and record popover with the time left and loop counters, input pickers, monitor buttons and meters on the lane headers and the mixer's AudioPath strips, Settings › Audio and › Recording (input device, Software Monitoring, I/O Buffer Size with its round-trip readout, latency trim, streaming sizes, record defaults, default monitor mode), the Track Synth and New MIDI Destination sheets with Measure off the main thread, and the take's waveform growing in the arrangement while it is written.

**Architecture:** Swift on top of plan 5d-1's cores, plus two small FFI lists.
- **`platform-macos` / `core-ffi`**: `list_sources`, `audio_input_devices()` and `midi_source_ports()` for the pickers (Task 1). Nothing else in the cores changes.
- **`VizDAWAppModel`** (tested with `FakeSession`): `AudioPreferences` keeps the audio settings in the app's preferences and hands them to the core at launch and on change; `RecordModel` gains the popover's state and readouts and the growing takes; `LaneInputs` builds the input pickers, cycles the monitor mode and holds the meters; `SynthSheets` and `MeasureJob` run the sheets, with Measure on a detached task; `ControlOutcome.measure` lets the control channel answer Measure when it ends.
- **`VizDAWEditors`**: the lane header's new controls, the lane menu's two items, the growing take in `ArrangementView`.
- **`VizDAW`**: the toolbar's `RecordControls`/`RecordPopover`, `StripInputView` in the mixer, `AudioSettingsView`/`RecordingSettingsView`, `TrackSynthSheet`/`NewMidiDestinationSheet`, and the control channel's non-blocking Measure.

**Tech Stack:** Swift 6 / SwiftPM (SwiftUI, AppKit, Observation, Swift Testing) on macOS 14+; Rust 2024 for the two lists (UniFFI 0.32.2).

**Spec:** `docs/superpowers/specs/2026-10-18-recording-audio-design.md`, §13 row "5d-2 — Record UI" (split from the former 5d row by plan 5d-1 Ruling 1, recorded again here as Ruling 1). This plan delivers:
- §6.9 Record UI: the transport toolbar (Record button, popover, time left, pass and keep counters), the lane menu's Track Synth…, the lane header's input picker, monitor button, meter with clip mark and link badge (not the FX button: plan 5g), the mixer's AudioPath input controls, Settings › Audio and Settings › Recording;
- §6.6's Software Monitoring switch and I/O Buffer Size with the round-trip readout (as settings the user sets);
- §6.7's Track Synth sheet and Measure button;
- §6.2's region drawing as it grows;
- §6.1 "If permission is denied, arming an audio lane shows a message pointing to System Settings › Privacy" (plan 5d-1 reports it as a fault at arm; the header's arm button is where it is pressed).

## Review Focus

The five failure modes a user is most likely to hit that the spec implies but does not spell out; each is pinned by named tests in its task.

1. **A setting changed at the wrong moment from Settings** (the buffer size while recording, a damaged preferences file, a value out of range). Expected: the refused change leaves both the core and the kept preference as they were and says why in red; damaged or out-of-range stored values fall back to their defaults one by one; nothing reaches the core twice. Pinned by `settingsAreKeptOnlyOnceTheCoreTookThem` and `damagedSettingsKeepTheirDefaults` (Task 1).
2. **Measure while the user keeps working** (from the sheet, or a script's `destination.measure_return` queued behind other calls). Expected: the window never freezes; one Measure at a time; the step is applied when it ends; the channel keeps answering other calls meanwhile and a call that already timed out never runs. Pinned by `measureRunsOffTheMainThreadAndShowsTheResult`, `measureAnswersWithTheMillisecondsAndAppliesTheStep` and the e2e `tracks_the_fake_synth` (Task 8).
3. **Saving during a take** (⌘S out of habit, Save As, an untitled project). Expected: ⌘S saves and says the take follows at Stop; Save As and an untitled Save open no panel and say why; nothing is lost. Pinned by `saveWhileRecordingSaysWhenTheTakeIsSaved` (Task 2).
4. **The input picker on a special lane** (a Track Synth return lane, a MIDI lane, a new lane with no destination, a device not opened yet). Expected: a return lane keeps its synth when its channels change; a MIDI lane offers sources and channels, not audio channels; a new lane offers both; before the device opened, two channels are offered. Pinned by `aReturnLaneKeepsItsSynth`, `midiChoicesAreSourcesAndChannels` and `audioChoicesNameTheDevicesChannels` (Task 4).
5. **Meters and clip marks over many polls** (a clip between polls, a recording's clipped samples, lanes disarmed while lit). Expected: a clip stays lit two seconds and then goes; meters show only for armed or Input-monitored audio lanes; the window polls fast only while one shows. Pinned by `metersShowArmedOrMonitoredLanesAndHoldTheClip` and `noMeterNoFastPoll` (Task 4).

## Plan Rulings

Decisions the spec leaves open, in the format "what — why — cost if wrong".

1. **Ruling (the split, from plan 5d-1 Ruling 1):** this plan is the second half of the former §13 row "5d — Record UI": the views and their models, on top of plan 5d-1's engine and channel work. It runs after 5d-1. Spec §13 has the two rows (amended with both plans).
   - Why: 5d carried 26 items on top of its own row; one plan would have been about 22 tasks, and the engine half must be reviewed apart from the views.
   - Cost if wrong: one more plan header and final review.
2. **Ruling (where the audio settings live):** in the app's preferences (`UserDefaults` key `VizDAW.audio`, JSON decoded field by field so one damaged value keeps only its own default), handed to the core before any document opens (`VizDAWApp.init`) and on every change. A change goes to the core first and is kept only once it took; `audio.set` goes through the same object, so a script's change is kept like a click.
   - Why: the spec makes them the machine's, not the project's; the core's settings are process-wide and forget at quit.
   - Cost if wrong: a setting would have to move into projects later (a file change).
3. **Ruling (record defaults):** Settings › Recording's count-in, pre-roll and passes as takes are what a document's record options start as when it opens; open documents keep theirs; the options are not saved in projects (as in 5c).
   - Why: the popover is per document; a default that rewrote open documents' options would surprise mid-session.
   - Cost if wrong: a changed default shows only in the next opened document.
4. **Ruling (the mixer's input controls):** an AudioPath strip's picker and monitor button edit the shown sequence's lane that plays through the strip's path: the first armed one, else the first; a strip no lane of the shown sequence plays through shows none.
   - Why: a path can be shared by several lanes; the strip needs one to edit, and the armed one is the one being set up.
   - Cost if wrong: with several lanes on one path, the others are set from their headers.
5. **Ruling (the picker's choices):** an audio lane (it plays to an audio path or has an audio input) offers "No Input", each device channel by its name and the pairs 1+2, 3+4, …; before the device has opened, two channels. A MIDI lane offers "All MIDI Inputs" and each source except VizDAW's own, then "Any Channel" and channels 1–16 (keeping the other half of the input). A lane with neither a destination nor an output offers both. Choosing channels on a return lane keeps its `return_of`.
   - Why: the spec's "audio channels by the device's channel names, or a MIDI port and channel"; pairs on odd channels are how interfaces label stereo inputs.
   - Cost if wrong: an even-odd pair (2+3) is set with `lane.set_input`.
6. **Ruling (Measure jobs; 5c-2 carries):** Measure runs on a detached task (`MeasureJob`) for the sheet and for the channel. The channel answers `destination.measure_return` when the job ends (within 15 s, the timeout `SynthCommands.extraTimeMs` already gives it), so its pump never blocks; and every queued call whose client was already answered `timeout` is skipped, not run late (final review finding 4).
   - Why: the 5c-2 final review's carry; Measure takes about 2.7 s, 10 s at most.
   - Cost if wrong: a script that ignored a `timeout` and expected the call to run anyway sees it dropped.
7. **Ruling (New MIDI Destination):** the sheet adds the destination ("Add Destination") and then points the lane at it ("Set Lane Destination"): two undo steps.
   - Why: plan 5d-1's `add_midi_destination` adds only; one step would need another core command for one sheet.
   - Cost if wrong: two Undos to take it back.
8. **Ruling (no sheet under the control channel):** with the channel on, Track Synth… and New MIDI Destination… open no sheet; the status line names `lane.track_synth` or `destination.add_midi` (control spec §7).
   - Cost if wrong: none (the commands exist).
9. **Ruling (the meters):** a lane shows its input meter while it has an audio input and is armed or monitors Input (when the core opens input for it, spec §6.1). Its level is the louder of its channels, falling back with the mixer meters' decay; a full-scale peak or a recording's new clipped samples light the clip mark for 2 s (plan 5d-1 Ruling 27). While any meter shows, the window polls at 33 ms as when playing.
   - Cost if wrong: a little more CPU while a lane stays armed.
10. **Ruling (time left):** free space beyond the 100 MiB at which recording stops, divided by rate × armed audio channels × bytes per sample of the project format. While recording it uses the core's reading (`RecordStateRow.freeBytes`); otherwise the project's volume (an untitled project's, the temporary folder's). With no armed audio lane there is no readout.
    - Cost if wrong: other programs writing to the disk make it optimistic.
11. **Ruling (Save As while recording):** the app opens no panel for Save As, or for Save in an untitled project, while recording, and says "Stop recording to use Save As: the take is being written into this project." (the core refuses the move anyway, `recording_busy`).
    - Cost if wrong: one more click after Stop.
12. **Ruling (the growing take):** drawn red over the lane's row from the later of the pass's start and the record range's start to what the writer has, clipped at Punch Out, from `recording_waveform`'s live peaks; it is placed by the roll (plan 5d-1 Ruling 21) and replaced by the region at Stop. Only the shown sequence's lanes draw one.
    - Cost if wrong: the take can jump by the round trip at Stop.
13. **Ruling (the lane header's layout):** the row keeps its 200-point width: the name narrows from 122 to 101 points for the monitor button left of M; the second line splits into the destination (92) and the input picker (90); the meter is a 3-point bar under them, inside the default 48-point lane.
    - Cost if wrong: long lane names truncate a little earlier.
14. **Ruling (the Track Synth sheet stays open):** after Track Synth the sheet stays open with Measure and Done, since Measure needs the return lane Track Synth makes.
    - Cost if wrong: one more button (Done).

    nonisolated static func kinds(_ lane: LaneRow) -> (audio: Bool, midi: Bool) {
        switch lane.input {
        case .audio: return (true, false)
        case .midi: return (false, true)
        case nil:
            let audio = lane.audioOut != nil
            let midi = lane.midiDest != nil
            return audio == midi ? (true, true) : (audio, midi)
        }

    public var metering: Bool { (document?.lanes ?? []).contains(where: Self.showsMeter) }

    public func level(_ lane: UInt64) -> Float { levels[lane] ?? 0 }

    public func isClipped(_ lane: UInt64) -> Bool { clipped.contains(lane) }

    /// Reads the input's peaks since the last read (the poll calls this
    /// while metering): each metered lane takes the louder of its channels;
    /// a peak at full scale, or a recording's new clipped samples, lights
    /// the clip mark for two seconds.
    public func pollMeters() {
        guard let m = document, metering else {
            if !levels.isEmpty { levels = [:] }
            if !clipped.isEmpty { clipped = [] }
            return
        }
        let raw = (try? m.session.inputLevels()) ?? []
        let t = now()
        var next: [UInt64: Float] = [:]
        for lane in m.lanes where Self.showsMeter(lane) {
            guard case .audio(let first, let stereo, _) = lane.input else { continue }
            let f = Int(first)
            let chans = stereo ? [f, f + 1] : [f]
            let peak = chans.compactMap { raw.indices.contains($0) ? MixerMath.sanitizedPeak(raw[$0]) : nil }.max() ?? 0
            next[lane.id] = max(peak, level(lane.id) * MixerMath.meterDecay)
            let count = m.record.state?.lanes.first { $0.lane == lane.id }?.clipped ?? 0
            if peak >= 1 || count > (clippedCounts[lane.id] ?? 0) { clipUntil[lane.id] = t + Self.clipHold }
            clippedCounts[lane.id] = count
        }
        if next != levels { levels = next }
        clipUntil = clipUntil.filter { $0.value > t && next[$0.key] != nil }
        let lit = Set(clipUntil.keys)
        if lit != clipped { clipped = lit }
    }
}

/// Settings › Audio's and › Recording's readouts and choices (plan 5d-2
/// Task 7; spec §6.6, §6.9).
extension AudioPreferences {
    /// The input devices the picker offers (tests replace it).
    public static var inputDevices: () -> [String] = { audioInputDevices() }

    /// The RAM cache sizes offered, MiB (64–8192; spec §5.5: 512).
    public static let cacheChoices: [UInt32] = [64, 128, 256, 512, 1024, 2048, 4096, 8192]

    /// The input device picker: "Same as output" (nil), every device, and
    /// the chosen one when it is not connected.
    public func inputDeviceChoices() -> [(title: String, name: String?)] {
        let devices = Self.inputDevices()
        var out: [(title: String, name: String?)] = [("Same as output", nil)]
        out += devices.map { ($0, $0) }
        if let chosen = settings.inputDevice, !devices.contains(chosen) {
            out.append(("\(chosen) (not connected)", chosen))
        }
        return out
    }

    /// The device's input as last read (Settings opens, the buffer size
    /// changes): its latencies and the round trip.
    public func readDevice(_ session: (any SessionProtocol)?) {
        let info = try? session?.inputInfo()
        if info != device { device = info }
    }

    /// The round-trip readout (spec §6.6): the device's measured round
    /// trip once it has opened, else the buffer's share of it.
    public static func roundTripText(_ info: InputInfoRow?, bufferFrames: UInt32) -> String {
        guard let info, !info.device.isEmpty, info.sampleRate > 0, info.roundTripFrames > 0 else {
            let ms = 2 * Double(bufferFrames) / 48_000 * 1_000
            return String(format: "About %.1f ms at 48 kHz, plus the device's own latency once it opens", ms)
        }
        let ms = Double(info.roundTripFrames) / info.sampleRate * 1_000
        var text = String(
            format: "Round trip %.1f ms (input %u + output %u + 2 × %u frames)", ms, info.inputLatencyFrames,
            info.outputLatencyFrames, info.bufferFrames)
        if info.bufferFrames != bufferFrames {
            text += "; \(info.device) runs at \(info.bufferFrames) frames"
        }
        return text
    }

    /// The latency trim's readout: "+12 frames (0.25 ms)".
    public static func trimText(_ frames: Int32, sampleRate: Double) -> String {
        let sign = frames > 0 ? "+" : ""
        let rate = sampleRate > 0 ? sampleRate : 48_000
        return String(format: "\(sign)\(frames) frames (%.2f ms)", Double(frames) / rate * 1_000)
    }

    /// Spec §6.2's thresholds, shown only.
    public static let lowDiskText = "Recording warns below 1 GB of free disk space and stops below 100 MB."
}

/// One Measure, run off the main actor (plan 5d-2 Ruling 6; 5c-2 carry,
/// final review finding 4): the session call (about 2.7 s, 10 s at most)
/// runs on a detached task and never blocks the main thread; the main
/// actor reads the result when it is done. The Track Synth sheet and the
/// control channel's `destination.measure_return` both use it.
@MainActor
public final class MeasureJob {
    public let dest: UInt64
    /// The measurement, or why it failed; nil while it runs.
    public private(set) var result: Result<MeasureRow, any Error>?
    /// Called on the main actor when it ends.
    public var onDone: (@MainActor (Result<MeasureRow, any Error>) -> Void)?

    public var isDone: Bool { result != nil }

    public init(session: any SessionProtocol, dest: UInt64) {
        self.dest = dest
        Task.detached { [weak self] in
            let r: Result<MeasureRow, any Error> = Result { try session.measureReturn(dest: dest) }
            await self?.finish(r)
        }
    }

    private func finish(_ r: Result<MeasureRow, any Error>) {
        result = r
        onDone?(r)
    }
}

    /// The shown sequence's armed audio lanes' takes while a pass records
    /// (spec §6.2: "the region draws as it grows"): from the later of the
    /// pass's start and the record range's start, to what the writer has
    /// (at most the punch-out). File frame `passStartFileFrame + i` is
    /// heard `i` frames after the pass's start; ticks and seconds map
    /// through the sequence's tempo. The placement is the roll's, so it
    /// can sit a few milliseconds off where Stop places the region.
    public func growingTakes() -> [GrowingTake] {
        guard isRecording, let m = document, let s = state, let seq = s.seq, seq == m.selectedSeq,
            let passTick = s.passStartTick, let rate = m.projectInfo?.format.sampleRate, rate > 0
        else { return [] }

        guard let end = (try? m.session.ticksAt(seq: seq, seconds: [endSeconds]))?.first, end > start else { return [] }

            GrowingTake(lane: $0.lane, startTick: start, endTick: end, fromFrame: from, toFrame: to)
